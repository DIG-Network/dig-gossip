# STR-004: Feature Flags

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 10.3](../../../resources/SPEC.md)

## Summary

Feature flags must match the SPEC Section 10.3 definitions exactly. Each feature gate controls conditional compilation of specific crate functionality: TLS backend selection (`native-tls`, `rustls`), relay support (`relay`), ERLAY transaction relay (`erlay`), and compact block relay (`compact-blocks`). The default feature set must enable the standard configuration for production nodes.

## Specification

### Feature Definitions

```toml
[features]
default = ["native-tls", "relay", "erlay", "compact-blocks", "dandelion"]
native-tls = ["dig-peer-protocol/native-tls", "dep:native-tls", "dep:tokio-native-tls"]
rustls = ["dig-peer-protocol/rustls", "dep:rustls", "dep:tokio-rustls", "dep:rustls-pemfile"]
relay = []
erlay = ["minisketch-rs"]
compact-blocks = ["siphasher"]
dandelion = []
tor = ["arti-client", "tokio-socks"]
```

### Feature Behavior

| Feature | Dependency | Conditional Compilation Effect |
|---------|-----------|-------------------------------|
| `native-tls` | Forwards to `dig-peer-protocol/native-tls`, plus `native-tls` / `tokio-native-tls` | Enables the native TLS backend via `create_native_tls_connector()` for outbound, and the OpenSSL inbound acceptor |
| `rustls` | Forwards to `dig-peer-protocol/rustls`, plus `rustls` / `tokio-rustls` / `rustls-pemfile` | Enables the rustls TLS backend via `create_rustls_connector()` for outbound, and the rustls inbound acceptor (CON-009) |
| `relay` | None | Enables `relay/` module compilation and relay-related code paths |
| `erlay` | `minisketch-rs` | Enables `gossip/erlay.rs` and ERLAY reconciliation code paths |
| `compact-blocks` | `siphasher` | Enables `gossip/compact_block.rs` and compact block code paths |
| `dandelion` | None | Enables `privacy/dandelion.rs` and Dandelion++ stem/fluff code paths |
| `tor` | `arti-client`, `tokio-socks` | Enables `privacy/tor.rs` and Tor/SOCKS5 proxy transport (opt-in) |

### Conditional Compilation

Modules gated by feature flags MUST use `#[cfg(feature = "...")]`:

```rust
// In src/relay/mod.rs or src/lib.rs
#[cfg(feature = "relay")]
pub mod relay;

// In src/gossip/mod.rs
#[cfg(feature = "erlay")]
pub mod erlay;

#[cfg(feature = "compact-blocks")]
pub mod compact_block;

// In src/privacy/mod.rs or src/lib.rs
#[cfg(feature = "dandelion")]
pub mod dandelion;

#[cfg(feature = "tor")]
pub mod tor;
```

### TLS Backend Selection

`native-tls` and `rustls` are mutually exclusive. The crate MUST compile with either one, and
MUST NOT compile with both enabled simultaneously (`dig_ecosystem#2756`):

```rust
#[cfg(feature = "native-tls")]
fn create_tls_connector(cert: &[u8], key: &[u8]) -> Result<...> {
    dig_peer_protocol::create_native_tls_connector(cert)
}

#[cfg(feature = "rustls")]
fn create_tls_connector(cert: &[u8], key: &[u8]) -> Result<...> {
    dig_peer_protocol::create_rustls_connector(cert)
}
```

**Enforcement:** a `#[cfg(all(feature = "native-tls", feature = "rustls"))] compile_error!(...)`
at the top of `src/lib.rs` makes the conflict a hard build failure rather than a documented
convention. This is not merely defensive: the two call sites that would otherwise have to choose
a backend when both are enabled disagree with each other today — `tls_connector_for_cert`
(`connection/outbound.rs`) prefers `native-tls`, `accept_loop` (`connection/listener.rs`) prefers
`rustls` — so an unguarded build with both features on dials out over one backend and accepts
inbound over the other in the same process. `--all-features` (and `--all-targets --all-features`,
which `cargo clippy` / `cargo doc` use by default) is the only ordinary way to reach this
combination; CI runs the two backends as separate feature legs instead (`ci.yml`).

## Acceptance Criteria

- [ ] Feature `native-tls` is defined and forwards to `dig-peer-protocol/native-tls`
- [ ] Feature `rustls` is defined and forwards to `dig-peer-protocol/rustls`
- [ ] Feature `relay` is defined with no additional dependencies
- [ ] Feature `erlay` is defined and depends on `minisketch-rs`
- [ ] Feature `compact-blocks` is defined and depends on `siphasher`
- [ ] Feature `dandelion` is defined with no additional dependencies
- [ ] Feature `tor` is defined and depends on `arti-client` and `tokio-socks`
- [ ] Default features are `["native-tls", "relay", "erlay", "compact-blocks", "dandelion"]`
- [ ] `cargo check --no-default-features --features native-tls` compiles without relay, erlay, compact-blocks, dandelion, or tor code
- [ ] `cargo check --no-default-features --features rustls` compiles with rustls TLS backend
- [ ] `cargo check --features relay` compiles with relay module
- [ ] `cargo check --features erlay` compiles with erlay module
- [ ] `cargo check --features compact-blocks` compiles with compact block module
- [ ] Relay module code is not compiled when `relay` feature is disabled
- [ ] ERLAY code is not compiled when `erlay` feature is disabled
- [ ] Compact block code is not compiled when `compact-blocks` feature is disabled

## Implementation Notes

- Primary file: `Cargo.toml` (feature definitions), `src/lib.rs` and various `mod.rs` files (conditional compilation)
- Dependencies: `siphasher` and `minisketch-rs` are optional dependencies
- Edge cases:
  - Enabling both `native-tls` and `rustls` simultaneously is a compile error BY DESIGN (the
    `compile_error!` guard in `src/lib.rs`, `dig_ecosystem#2756`) — not an incidental duplicate-
    symbol failure, an explicit, named one. `cargo check --all-features` and
    `cargo check --no-default-features --features native-tls,rustls` both MUST fail with that
    message; neither may silently resolve to one backend.
  - A genuinely TLS-backend-free build (`--no-default-features`, neither feature enabled) is
    INTENDED as a third configuration — `discovery/node_discovery.rs` and
    `service/gossip_service.rs` each carry a dedicated no-TLS fallback arm for API-001/API-002
    unit tests — but as of `dig_ecosystem#2756` it does NOT currently compile (unrelated,
    pre-existing errors: `dig_peer_protocol::{Client, ClientState}` feature-gated out with no
    matching cfg-guard at their call sites, and `IntroducerClient::query_peers` /
    `register_with_introducer` do not exist). Tracked separately; do not assume this shape builds
    until that is fixed.
  - Code that references relay types outside the relay module must also be feature-gated
  - Test modules that test feature-gated code must use appropriate `#[cfg(feature = "...")]` attributes
